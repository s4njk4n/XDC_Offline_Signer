Get the offline signer

One file, no installation

The signer is a single HTML file of about 600 KB. It opens in any modern browser (Chrome, Firefox, Edge, Brave), contains every library it needs, and is blocked by its own security policy from making any network connection at all.

Download signer v__VERSION__

SHA-256 __OFFLINE_SHA__

Check the SHA-256 before copying it across, against the value in the GitHub release. On Linux or macOS run sha256sum xdc-offline-signer.html; on Windows, certutil -hashfile xdc-offline-signer.html SHA256.

Setting up the offline computer

  1. Use a spare laptop with a webcam. Remove or disable its Wi-Fi and Bluetooth, and don't plug in a network cable.
  2. For the strongest setup, boot a fresh Linux live USB (for example Ubuntu or Tails) rather than an everyday operating system.
  3. Copy xdc-offline-signer.html across on a USB stick and open it in the browser. Allow the camera when asked.
  4. Load your key, scan the request from this page, check what it shows, sign, and hold the phone up to the signed QR code.
  5. Close the browser tab when finished. The key is held only in that tab's memory.

Things to know

What each side checks

The signer builds the transaction itself from your choices and describes what it signs from the transaction bytes, not from the label this page gave it. This page then decodes the signed transaction independently, recovers the sender from the signature, compares every field with what you prepared, and asks the network whether it would succeed.

Nonces

Every transaction from a wallet carries the next number in sequence. A request prepared here uses the wallet's next nonce. If anything else is sent from the wallet in the meantime, the signed transaction will be rejected harmlessly, so prepare it again.

Sending everything

A plain transfer to a wallet costs exactly 21,000 gas, so the signer can send the balance minus the fee and leave exactly zero. Masternode owner wallets receive rewards every epoch, so a reward landing between preparing and broadcasting stays behind as a small remainder.

Unvote, then withdraw

Unvoting and resigning don't pay anything out. They move the stake into your withdrawal queue with an unlock block. Once the chain passes that block, the Withdraw tab lists the entry as ready and you sign one Withdraw transaction per entry.

Resigning

Only the wallet that proposed the masternode can resign it. The candidate leaves the masternode set for good, and your own stake on it waits out the candidate unlock delay, which is longer than the voter delay. Other people's votes on it stay theirs to unvote.

Tokens

Token transfers pay their fee in XDC, so the wallet needs a little XDC as well. The token's symbol and decimals are read from the chain here and passed to the signer for display; the signer also shows the raw amount so you can confirm the decimals.

Stuck transactions

If a broadcast transaction sits unmined, for example because its gas price was too low, Cancel stuck sends 0 XDC to yourself with the same nonce and a higher gas price. Whichever is mined first wins, so at worst the cancel is rejected and costs nothing.

Your choice of RPC

Reads and broadcasts use the free public Plugin XDC RPC by default, with the XinFin public RPCs as fallbacks. Under Network settings you can use your own node. It's saved only in this browser.

Transaction format

Transactions are standard legacy XDC transactions with EIP-155 replay protection, so a signature for Mainnet (chain ID 50) can't be replayed on Apothem (51) or any other chain.
